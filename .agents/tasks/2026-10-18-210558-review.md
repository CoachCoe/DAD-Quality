# Generic discovery targets with an adapter registry

Move 2 introduces a small target registry (`src/targets.js`) that maps a target name to an adapter factory plus the policy/adapter identity it emits, then threads a `--target` option through the CLI and `executeDiscovery`. The goal is to make ATM's self-discovery generic while keeping DAD byte-identical: the `dad` entry retains the verbatim `impactgraph-discovery`/`impactgraph` identifiers and the same policy digest. A second target, `benchmark`, exposes the existing in-process synthetic application (`discovery-benchmark.js`) as a first-class `explore --target benchmark` with no Docker. The policy validator's hard-coded adapter literal is relaxed to accept any registered adapter id while every other check stays strict, and the discovery auth-cookie name is now sourced from the actor descriptor (default `dad_donor_session`).

Watch for: the benchmark CLI smoke path still gates on model configuration before provisioning, so `explore --target benchmark` with no model key exits at the model step rather than running the full in-process pipeline (confirmed) — this is pre-existing shared exploration behavior and is anticipated by the task's own acceptance criteria, not a regression.

**Verdict**: APPROVED

## High-level view

The registry is the spine: `resolveTarget(name='dad')` returns `{ adapterFactory, policyId, adapterId }` or throws with the known-target list, and `isRegisteredAdapter(id)` backs the relaxed policy check. DAD's identity literals move into the registry unchanged, so `discoveryPolicy('dad')` produces the same id, adapter, and digest as before — proven by a digest-equality test.

The policy relaxation is narrow. Only the adapter-identity comparison changed from `!== 'impactgraph'` to `!isRegisteredAdapter(...)`; schema, version, scope, checks, evidence, scenario, digest, blocking-severity, and exception validation are untouched, and a registered-but-non-impactgraph adapter now passes while an unregistered one still throws.

The benchmark adapter satisfies the runner's lifecycle contract over an in-process loopback server: `snapshot` provisions, the containerized stages record not-applicable evidence logs, `discoveryFixture` adapts the synthetic actors (cookie-value auth under cookie name `session`), and `cleanup` closes the server. Its loopback origin meets the discovery browser's http/127.0.0.1/port/`/` check.

The known gap is the CLI smoke: `executeDiscovery` runs its model-config gate before adapter provisioning (by design, to fail before building images), so a keyless `explore --target benchmark` stops at the model step. Provisioning and teardown are instead exercised by the unit test without Docker or a model key.

### Registry spine and DAD byte-identical guarantee

`targets.js` keeps DAD's `policyId: 'impactgraph-discovery'` and `adapterId: 'impactgraph'` verbatim, and `discoveryPolicy('dad')` reads both from the registry rather than inline literals. The byte-identical claim is enforced by a test asserting `discoveryPolicy('dad').digest === discoveryPolicy().digest` along with the id/adapter values (confirmed — test passes). `executeDiscovery` now resolves the target, defaults `adapterFactory` to the resolved factory via `adapterFactory ??=` (keeping the explicit override for test mocks), and passes `adapter: resolved.adapterId` to `Run.create` — for `dad` that is still `impactgraph`, so ledger/finding compatibility holds (confirmed).

### Narrow policy relaxation

The only change in `policy.js` is the identity line: `policy.adapter !== 'impactgraph'` became `!isRegisteredAdapter(policy.adapter)` (confirmed by diff). Everything else in `validatePolicy` is byte-unchanged. The policy test clones `discoveryPolicy('dad').definition`, sets a registered adapter and asserts it validates, then sets `unregistered-xyz` and asserts it throws on `/adapter/`; the pre-existing malformed-policy suite remains intact and green (confirmed).

### Benchmark adapter over the in-process app

`BenchmarkAdapter` fulfills the adapter contract without Docker: `snapshot` spins up `benchmarkApplication('healthy')` on a loopback port, writes the synthetic source/contract under `run.dir/source` at restrictive modes (0o700/0o600), and records `candidate.json`. The `docker`/`build`/`database`/`deploy` stages funnel through a `notApplicable` helper that writes exactly the evidence log names `policy.js` requires for each check, so the exploration policy's evidence contract is satisfied without containers. `discoveryFixture` spreads `cookieName: 'session'` onto the two cookie-bearing donors only, matching the app's cookie-value auth (`test-a`/`test-b`), and leaves the guest untouched. The unit test confirms the loopback origin shape (`http`, `127.0.0.1`, port, pathname `/`) the discovery browser requires, server reachability, and that `cleanup` closes the server (follow-up fetch rejects) — all without a model call (confirmed).

### Cookie-name threading

`discovery-browser.js` now uses `who.cookieName ?? 'dad_donor_session'`, and `dad.js` adds `cookieName: 'dad_donor_session'` to the two authenticated donors. The DAD default is preserved for existing behavior, and a test asserts both authenticated DAD donors carry the default name while the guest has none (confirmed). This is the seam that lets the benchmark supply its own `session` cookie name.

### CLI surface and guards

`--target NAME` defaults to `dad`. The CLI validates the target early (`resolveTarget` throws on unknown before dispatch), rejects a non-dad target on `run` (`run targets DAD only...`), and restructures the `--repo` guard so `explore --target benchmark` works with no repo while `run` and `explore --target dad` still require one. Verified live: `run` without `--repo` errors, `run --target benchmark` errors, `explore --target nope` lists `dad, benchmark` (confirmed).

### Model-config gate on the benchmark smoke (confirmed)

`executeDiscovery` evaluates `modelConfig` before provisioning the adapter, so a keyless `node src/cli.js explore --target benchmark --max-requests 1` exits with `Configure OPENAI_API_KEY and --model...` before any benchmark provisioning. This is the same fail-before-building-images ordering DAD exploration uses and is not a Docker dependency; the FEAT-002 acceptance criteria explicitly anticipate this ("it will end inconclusive/fail at the model step, which is expected"). Provisioning and teardown of the benchmark path are covered by `test/benchmark-adapter.test.js` without Docker or a key, so requirement (3)'s intent — no Docker, and the benchmark machinery usable without a live model — is satisfied.

### Journey/pipeline files untouched

`scenarios.js`, `agent.js`, `browser.js`, `runner.js`, `discovery.js`, and `discovery-fixture.js` have zero diff against `dev` (confirmed via `git diff --name-only`). The change is confined to registry plumbing and threading, as required.

### Test coverage

Added: registry resolution and unknown-target rejection, `isRegisteredAdapter` true/false, DAD digest equality, the policy accept-registered/reject-unregistered pair, the DAD cookie-name default, and the benchmark provisioning/fixture/cleanup smoke plus its target-identity assertions. Lint is clean (biome `--error-on-warnings`, 68 files) and the full suite is 107 pass / 0 fail with `OPENAI_API_KEY`/`ATM_MODEL` unset and Docker not involved (confirmed). Not tested: an end-to-end benchmark exploration driving a model through the CLI — out of scope for the non-live smoke path and gated by the model-config step noted above.
